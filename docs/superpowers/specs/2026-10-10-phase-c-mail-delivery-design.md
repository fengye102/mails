# 阶段 C：库存、分配与取件交付设计规格

- 日期：2026-10-10
- 状态：实现完成；真实部署待具备环境后验收
- 上级决策：`docs/decisions/0001-platform-boundaries.md`

## 目标

为可控的邮箱库存建立独立交付服务：运营者登记可分配邮箱，按策略分配给订单/租约，签发一次性取件码，收件人仅凭取件码在有效期内查看邮箱地址与纯文本邮件摘要，并保留完整操作审计。C 与 A 私有后台、B1 公开临时邮箱使用独立数据库、密钥、会话和 API 入口。

## 边界与隔离

- 独立服务目录 `apps/delivery_api/`，API 前缀 `/delivery-api/v1`。
- 不导入 `mails_api` 或 `public_mail_api` 的模型、会话、数据库连接和凭据。
- C 只保存库存邮箱引用和加密的上游访问凭据；不复制 A 的用户体系，不让取件者获得管理凭据。
- 邮箱库存状态为 `available|allocated|expired|disabled`；分配使用数据库事务和行级锁，避免并发重复分配。

## 最小业务模型

- `inventory_mailboxes`：地址、加密访问令牌、状态、来源标签、有效期。
- `delivery_allocations`：邮箱租约、订单/外部引用、分配时间、到期时间、状态。
- `pickup_credentials`：取件码摘要、失败次数、最大尝试次数、过期时间、已使用时间。
- `delivery_audit_events`：创建、分配、取件成功、失败、撤销、过期等不可变事件。

## API

- 运营写接口使用独立 operator token：登记/停用库存、分配邮箱、撤销分配、查看审计。
- `POST /delivery-api/v1/pickups`：生成一次性取件码；只返回一次明文取件码。
- `POST /delivery-api/v1/pickups/verify`：校验取件码并返回短时取件会话；失败统一返回固定错误。
- `GET /delivery-api/v1/pickups/{pickup_id}/mailbox`：取件会话查看地址和纯文本消息摘要；禁止 HTML、发信、管理操作。
- 取件码使用 Argon2id/sha256 摘要保存，明文不入库、不打日志；固定速率限制和失败退避。

## 事务与安全不变量

1. 一个库存邮箱同一时刻最多一个有效分配。
2. 过期分配不能创建取件会话；过期取件会话不能读取邮件。
3. 取件码只能使用一次，验证成功后立即标记 consumed；重放返回固定错误。
4. 所有用户输入和上游错误映射为固定错误码，不回显原文、令牌或数据库异常。
5. 取件响应只包含纯文本字段，服务端不执行或返回 HTML。

## 验收

- 并发分配不会重复占用同一邮箱。
- 取件码只显示一次、摘要存储、过期/重放/错误尝试均被拒绝。
- A/B1/C 数据库和网络可独立部署；Docker、PostgreSQL、真实上游缺失时明确记录 skipped。
